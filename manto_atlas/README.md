# Epimanto research preview

Epimanto is an independent Symmachus project built on MANTO data, for the
local-culture and settlement-persistence study. The existing `manto_atlas` module
and build command retain their technical names. The exporter reads existing tables in a transaction marked READ ONLY; it
never initializes the schema, imports MANTO, retrains models or publishes files.
It uses no LLM/API calls, external JavaScript, fonts, map tiles or analytics.

## Build locally

```sh
uv run build_manto_atlas.py \
  --database-url "host=/var/run/postgresql port=5433 dbname=pausanias user=gregb options='-c search_path=manto_stage_23079055_20261109,public'" \
  --release-record-id 23079055 \
  --output-dir tmp/epimanto-preview
```

Use the correct configured role for the execution account. The example is a
manual read-only run on Raksasa, not a proposed service-account grant. Never fall
back to retired PostgreSQL 16 or the legacy SQLite database. All generated data
stay in the ignored output directory. Open its `index.html` locally, or serve the
whole directory with a local web server. No live publication occurs.
The staging-plus-public search path is for this read-only exporter only; do not
copy it into a writing pipeline. It does not activate v3 in the public tables.

## What is implemented

- Overview with source release, coverage and clear research-stage limitations.
- Geographic neighbours at 25/50/100 km and weighted figure-profile comparisons.
- Selected local-identity relation profiles, binary deduplication and asymmetric
  containment. Empty profiles remain unknown rather than maximally distinctive.
- Schematic geographic map and an experimental higher-level network aggregating
  nearby shared-figure pairs by MANTO name-label suffixes. These are not verified
  settlements or cultural communities.
- Searchable, paginated Pausanias claim register with temporal/status filters,
  Greek context, existing project translations, original passage links and
  explicit unreviewed candidate entity matches.
- Historical corrected model comparison, methods and GNN benchmark plan. No new
  outcome model or GNN is trained by this preview.
- Shareable query parameters, keyboard-operable graph nodes, mobile layout,
  escaped source text, a restrictive content-security policy and build hashes.
- Epimanto branding and a local release packager for versioned assets and a
  final single-file entrypoint switch. Packaging does not connect or publish.

## Prepare a publishable bundle locally

```sh
uv run prepare_epimanto_release.py \
  --source tmp/epimanto-preview \
  --output tmp/epimanto-release-bundle
```

Use a completed preview generated by `build_manto_atlas.py`. The packager verifies
its five exact assets and checksums, pinned MANTO ID and schema, rejects symlinks
and unrelated manifest paths, and refuses to overwrite an existing bundle.
It preserves the original assets under a content-addressed `_releases/` path
and rewrites only the root entrypoint's current five asset/download references.

The future publisher must serialize the whole operation: upload `_releases/`
successfully first, then upload only the root `index.html` using rsync's normal
temporary-file rename. Do not use `--inplace`, `--append`, an external temporary
directory or `--delete`. The entrypoint switch is atomic, not the two-command
operation. Release immutability is a publisher convention, not a restriction
enforced by the site's write key. Retain older assets and the previous complete
local bundle for cached pages and rollback. The root entrypoint has its own hash
in `deployment.json`; its hash differs from the original release index's hash.

All paths stay inside htdocs, so this layout needs no shell or parent-directory
access beyond the approved restricted publishing key. Neither packaging nor
these instructions grant permission to publish. Source access, web serving,
DNS/TLS and the production content gate remain separate checks. Future new
assets, CSS URLs, inline fetches or alternate HTML references need explicit
packaging validation and browser tests.

The full methodology is
`documentation/manto_local_culture_survival_plan_2026-11-09.md`. This preview is
not a substitute for its source-date, identity and endpoint-adjudication gates.
